1. Introduction & Objectif

Ce rapport présente les résultats des tests unitaires automatisés pour le Module 1 (Contrôle d'accès et cycle de vie des comptes). L'objectif est de s'assurer de la sécurité de notre site a travers nos barrières de sécurité (validation des données, hachage, sessions, middlewares) face aux diverses incohérences de connexion qu'on pourrait rencontrer.

3. Fiches de Détail des Cas d'Erreur (Cliquez pour dérouler)

🔍 CT_01 : Procédure d'inscription incomplète

Description : Vérifie que l'API bloque l'enregistrement si l'étudiant ne fournit pas toutes les données requises.

Payload JSON envoyé :

{ "nom": "Lissassi", "prenom": "Meschac" }

Réponse attendue de l'API :

{ "error": "Veuillez remplir tous les champs" }
🔍 CT_02 : Tentative de connexion sans mot de passe

Description : S'assure que le serveur interrompt immédiatement le traitement si l'un des paramètres d'authentification manque.

Payload JSON envoyé :

{ "email": "test@etudiant.com" }

Réponse attendue de l'API :

{ "error": "Veuillez remplir tous les champs" }
🔍 CT_03 : Identifiants invalides (Compte introuvable)

Description : Test du comportement du système face à un email n'existant pas dans la base de données MySQL.

Payload JSON envoyé :

{ "email": "intrus@ifri.com", "mot_de_passe": "password123" }

Réponse attendue de l'API :

{ "error": "Identifiants incorrects" }
🔍 CT_04 : Interception par le Middleware (@login_required)

Description : Vérifie que le décorateur bloque instantanément une requête vers un espace privé si la variable de session n'existe pas.

Méthode HTTP : GET /dashboard (Sans cookie de session)

Réponse attendue de l'API :

{ "error": "Accès refusé. Veuillez vous connecter." }
🔍 CT_05 : Réinitialisation sur compte inexistant

Description : Empêche la modification d'un mot de passe pour un utilisateur inexistant.

Payload JSON envoyé :

{ "email": "inconnu@ifri.com", "nouveau_mot_de_passe": "NewPass123!" }

Réponse attendue de l'API :

{ "error": "Aucun compte associé à cet email" }
